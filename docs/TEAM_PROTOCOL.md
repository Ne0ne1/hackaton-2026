# Командный протокол — «Билет с видом на экран»

Единая точка правды для двух AI-исполнителей на хакатоне «Код Единства».  
Репозиторий: https://github.com/Ne0ne1/hackaton-2026

**Это правила заменяют** прежнее распределение ролей. Старые формулировки «3D делает Cursor / MiniMax не трогает SeatView3D» **недействительны**.

Перед любой задачей прочитай этот файл, `docs/INTEGRATION_CONTRACT.md`, `docs/TASKS.md` и `docs/DECISIONS.md`.

## 1. Конкурсный кейс

Продукт: веб-сервис покупки билетов в кино «Билет с видом на экран».

Обязательный функционал:

1. Выбор кинотеатра и сеанса.
2. Схема свободных и занятых мест.
3. Разные цены в зависимости от места.
4. Реальный качественный 3D-вид экрана с любого выбранного места.
5. Изменение перспективы при перемещении вперёд, назад и в сторону.
6. Покупка и сохранение билета; после покупки место занято.
7. Понятный, красивый и стабильный интерфейс.

Приоритет — максимум баллов по критериям жюри (включая дизайн). Telegram не делать.

## 2. Критерии жюри (ориентир)

| Фокус жюри | Как закрываем |
|------------|---------------|
| Покупка end-to-end | Cursor: выбор → место → сохранение → sold |
| Качественный 3D с места | **MiniMax**: реалистичный зал, камера, свет, материалы |
| Удобство и дизайн | Cursor — общий UI/схема; MiniMax — 3D и модули опыта |
| Доп. ценность | SeatMatch → SeatCompare / SpatialSound → HonestView |

## 3. Роли (новое распределение)

### Исполнитель A — Cursor

Ветка: `feat/cursor-core`.

Отвечает за:

- архитектуру приложения;
- backend и API (`src/core/**`);
- данные кинотеатров, сеансов, кресел как **источник истины** (`src/data/**`, `src/types/hall.ts`);
- 2D-схему зала (`src/components/SeatMap.tsx`);
- покупку, хранение билетов, статусы мест;
- `src/App.tsx`, общие стили, навигацию;
- подключение модулей MiniMax;
- сборку, тестирование, деплой;
- `docs/TASKS.md`, `docs/DECISIONS.md`, утверждение контракта.

**Cursor НЕ разрабатывает и НЕ полирует 3D-сцену.**  
Не трогает: `src/components/SeatView3D.tsx`, `src/components/SeatView3D.css`, `src/scene/**`, `src/experience/**` (кроме явной интеграции props в `App.tsx`).

### Исполнитель B — Cline + MiniMax M3

Ветка: `feat/cline-experience`.

**Единственный владелец визуального 3D:**

- `src/components/SeatView3D.tsx` (+ CSS сцены);
- `src/scene/**` при необходимости;
- геометрия кинозала в сцене (кресла, ряды, экран, стены, потолок, пол, проходы);
- материалы, освещение, атмосфера;
- камера с выбранного кресла и анимации перемещения;
- оптимизация WebGL.

Также владеет модулями опыта:

- SeatMatch, SeatCompare, HonestView, SpatialSound (+ UI/тесты);
- `docs/CLINE_PROGRESS.md`.

Может перерабатывать существующий `SeatView3D`, но:

- **не** создаёт второй независимый 3D-движок;
- **не** дублирует источник данных кресел (данные — только из контракта Cursor);
- внешние props `SeatView3D` сохраняет: `hall`, `cameraView`, `occupiedSeatIds`.

Нужны правки API/камеры в ядре — описать запрос; реализует Cursor по согласованию.  
Не меняет `docs/TASKS.md` / `docs/DECISIONS.md`.

### Codex / OpenRouter

Без изменений по смыслу: Codex — ТЗ и аудит; OpenRouter — только после явного подтверждения.

## 4. Приоритеты (новые)

| Уровень | Что | Кто |
|---------|-----|-----|
| **P0** | Работающая покупка **+ качественный настоящий 3D** | Cursor (покупка/схема) + MiniMax (3D) |
| **P1** | Интеграция SeatMatch | Cursor подключает; MiniMax модуль |
| **P2** | SeatCompare и пространственный звук | MiniMax |
| **P3** | HonestView и доп. улучшения | MiniMax |

## 5. Правила Git

Ветки: `main` (стабильная), `feat/cursor-core` (Cursor), `feat/cline-experience` (MiniMax).

1. Параллельная работа только в своих ветках.
2. Не пушить продукт в `main` без разрешения.
3. Запрещены force push, `reset --hard`, удаление чужих коммитов, автослияние конфликтов.
4. Перед стартом: `git status`, `git fetch --all`.
5. Секреты не коммитить.
6. Push — только после разрешения пользователя.
7. Канонический remote для напарника — **GitHub** `Ne0ne1/hackaton-2026` (`git push github <ветка>`). `origin` может быть Cursor Origin — не путать.

Коммиты только с правилами (без кода) MiniMax может переносить через `cherry-pick`.

## 6. Разделение файлов

**Cursor:** `src/core/**`, `src/data/**`, `src/types/hall.ts`, `src/components/SeatMap.tsx`, `src/App.tsx`, `package.json`, общие стили приложения, журналы Cursor.

**MiniMax:** `src/components/SeatView3D.tsx`, `src/components/SeatView3D.css`, `src/scene/**`, `src/experience/**`, `docs/CLINE_PROGRESS.md`.

**Общие точки:** Cursor монтирует `<SeatView3D hall cameraView occupiedSeatIds />` в `App.tsx`. Breaking API — только через обновление контракта Cursor.

## 7. Контракт

`docs/INTEGRATION_CONTRACT.md` v1: `HallGeometry`, `SeatCameraView`, `getSeatCameraView`, `getHallGeometryForSession`, `getSeatsWithStatus` — предоставляет Cursor.  
MiniMax строит сцену на этих данных.

## 8. Порядок интеграции

1. MiniMax улучшает 3D в `feat/cline-experience` (и модули опыта).
2. Cursor держит покупку/схему/API в `feat/cursor-core`.
3. Перенос 3D/модулей — cherry-pick или PR; Cursor подключает в `App` без переписывания сцены.
4. Конфликты зон — остановка и согласование.

## 9. Сдача

Покупка работает; 3D качественный и меняет перспективу; sold после покупки; модули не ломают P0; `npm run build` (и тесты, если есть).
