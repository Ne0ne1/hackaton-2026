# Командный протокол — «Билет с видом на экран»

Единая точка правды для двух AI-исполнителей на хакатоне «Код Единства».  
Репозиторий: https://github.com/Ne0ne1/hackaton-2026

Перед любой задачей прочитай этот файл, `docs/INTEGRATION_CONTRACT.md`, `docs/TASKS.md` и `docs/DECISIONS.md`.

## 1. Конкурсный кейс

Продукт: веб-сервис покупки билетов в кино «Билет с видом на экран».

Обязательный функционал (P0):

1. Выбор кинотеатра и сеанса.
2. Схема свободных и занятых мест.
3. Разные цены в зависимости от места.
4. Реальный 3D-вид экрана с любого выбранного места.
5. Изменение перспективы при перемещении вперёд, назад и в сторону.
6. Покупка и сохранение билета; после покупки место занято.
7. Понятный, красивый и стабильный интерфейс.

Приоритет — максимум баллов по критериям жюри, а не максимум функций.

Telegram-интеграцию не реализовывать.

## 2. Критерии жюри (ориентир)

Точная таблица баллов организаторов может уточняться. Пока оцениваем успех по покрытию обязательного функционала и качеству демонстрации:

| Фокус жюри | Как закрываем |
|------------|---------------|
| Покупка билета end-to-end | Выбор → место → оплата/сохранение → место занято |
| 3D-вид с места | Общий рендерер Cursor; перспектива меняется при смене места |
| Удобство и стабильность | Чистый UI, без падений на основном сценарии |
| Доп. ценность | SeatMatch → SeatCompare → HonestView / SpatialSound только если P0 готов |

Дополнительные модули не должны ломать обязательный сценарий.

## 3. Роли

### Исполнитель A — Cursor (основной разработчик)

Ветка: `feat/cursor-core`.

Отвечает за:

- архитектуру приложения;
- структуру кинотеатров и сеансов;
- хранение данных и backend;
- схему зала и кресел;
- основную 3D-сцену, камеры и перспективу;
- покупку и сохранение билетов;
- навигацию, сборку, интеграцию модулей и деплой;
- обновление `docs/TASKS.md` и `docs/DECISIONS.md`;
- финальное слияние в `main` после проверки.

Не переписывает модули MiniMax без явной причины и согласования.

### Исполнитель B — Cline + MiniMax M3

Ветка: `feat/cline-experience`.

Отвечает за отдельные модули:

- **SeatMatch** — рекомендация лучших свободных мест (цена, расположение, качество обзора);
- **SeatCompare** — сравнение вида с двух мест;
- **HonestView** — демонстрация возможного перекрытия экрана зрителями впереди;
- **SpatialSound** — звук в зависимости от положения относительно колонок;
- UI и тесты этих модулей.

Получает ТЗ от Codex. Не меняет архитектуру Cursor. Использует общий 3D-рендерер. Не создаёт второй движок и альтернативную модель данных.

Журнал прогресса: `docs/CLINE_PROGRESS.md` (только в своей ветке). Общие `docs/TASKS.md` и `docs/DECISIONS.md` не редактирует.

Правила исполнителя: `.clinerules/01-minimax-executor.md` и этот протокол.

### Codex — ТЗ и аудит

- Составляет технические задания для MiniMax и при необходимости уточняет контракты.
- Проводит аудит готовности и границ модулей через официальный CLI (`scripts/run-codex.sh`).
- Не редактирует одновременно те же файлы, над которыми работают Cursor или Cline.
- Не является третьим параллельным разработчиком продукта в той же зоне файлов.

### OpenRouter

Только резерв после исчерпания лимита подписки и только с явным подтверждением пользователя.

## 4. Приоритеты функций

| Уровень | Что | Кто |
|---------|-----|-----|
| **P0** | Покупка, сохранение, 3D-вид с любого места, удобство и стабильность | Cursor |
| **P1** | SeatMatch, затем SeatCompare | MiniMax после появления контракта и базового зала |
| **P2** | HonestView, SpatialSound | MiniMax |
| **P3** | Полировка | по остатку времени |

P1–P3 не блокируют и не ломают P0.

## 5. Правила Git

Ветки:

| Ветка | Назначение |
|-------|------------|
| `main` | стабильная интегрированная версия |
| `feat/cursor-core` | работа Cursor |
| `feat/cline-experience` | работа MiniMax / Cline |

Правила:

1. Оба исполнителя работают **параллельно**, но только в своих ветках.
2. Прямой push в `main` агентам запрещён (кроме согласованного коммита инфраструктуры/инструкций по явной просьбе человека).
3. Запрещены: `force push`, `reset --hard`, удаление чужих коммитов, автоматическое слияние конфликтующих изменений.
4. Перед стартом дня: `git status`, сохранить работу, `git fetch` / актуализировать от `main`.
5. Секреты, `.env`, ключи API не коммитить.
6. MiniMax: локальный коммит после проверок; `git push` только после разрешения пользователя.
7. Cursor: то же для своей ветки; в `main` вливает только после ручной/осознанной интеграции.

### Создание рабочих веток (для участников)

```bash
git fetch origin
git checkout main
git pull --ff-only origin main

# Участник A (Cursor)
git checkout -b feat/cursor-core
git push -u origin feat/cursor-core

# Участник B (Cline / MiniMax)
git checkout main
git pull --ff-only origin main
git checkout -b feat/cline-experience
git push -u origin feat/cline-experience
```

## 6. Разделение файлов

Пока каркас продукта ещё не создан, владение задаётся по зонам ответственности, а не по выдуманным путям.

**Cursor владеет (когда появятся):** базовая архитектура, данные зала, 3D-рендерер и камера, backend и покупка, общие маршруты и конфигурация приложения, `package.json`, модель Seat, `docs/TASKS.md`, `docs/DECISIONS.md`, `docs/INTEGRATION_CONTRACT.md` (утверждение факта).

**MiniMax владеет (когда появятся):** компоненты и тесты SeatMatch, SeatCompare, HonestView, SpatialSound; вспомогательные функции только этих модулей; `docs/CLINE_PROGRESS.md`.

**Общие файлы** (`package.json`, главные маршруты, модель Seat, корневая конфигурация) редактирует только Cursor либо другой исполнитель после явного согласования в чате/задаче.

Реальные пути фиксируются Cursor в `docs/INTEGRATION_CONTRACT.md` после появления кода. Нельзя ссылаться на несуществующие пути как на готовые.

## 7. Контракты между модулями

Источник: `docs/INTEGRATION_CONTRACT.md`.

- Пока кода нет — контракты **предварительные**.
- Перед подключением доп. модулей Cursor подтверждает фактические интерфейсы.
- MiniMax следует утверждённым интерфейсам и не меняет их самостоятельно.
- Нужен общий доступ к: id места, ряд/номер, категория/цена/статус, координаты кресла, размеры и положение экрана, геометрия зала, 3D-вид по месту, точка подключения плагинов опыта.

## 8. Порядок интеграции

1. Cursor доводит P0 в `feat/cursor-core` и обновляет фактический контракт.
2. MiniMax разрабатывает P1–P2 в `feat/cline-experience` против утверждённого контракта.
3. Cursor мержит свою ветку в `main` (после разрешения пользователя).
4. Cursor подтягивает `main` в интеграционную проверку и подключает модули MiniMax через согласованные точки расширения.
5. Конфликты не «авточинятся»: при пересечении файлов — остановка, согласование, правка одним владельцем зоны.
6. Cursor переносит итог MiniMax из `docs/CLINE_PROGRESS.md` в `docs/TASKS.md` после интеграции.

## 9. Порядок проверки и сдачи

Перед сдачей:

1. Основной сценарий покупки проходит без ошибок.
2. 3D-вид меняется при смене места (вперёд/назад/в сторону).
3. Купленное место отображается занятым после сохранения.
4. Доп. модули либо работают через контракт, либо отключены и не ломают P0.
5. Запущены существующие проверки проекта (тест / линт / сборка — что есть).
6. В `main` нет секретов; инструкции и контракт актуальны.

Ответы агентов, планы и отчёты — на русском.
