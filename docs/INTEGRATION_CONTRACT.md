# Контракт интеграции модулей

Статус: **предварительный**. Кода продукта ещё нет.  
Утверждает фактические интерфейсы: **Cursor** после появления реализации.  
MiniMax следует утверждённой версии и не меняет контракт самостоятельно.

Связанный протокол: `docs/TEAM_PROTOCOL.md`.

## 1. Цель

Договориться, как дополнительные модули (SeatMatch, SeatCompare, HonestView, SpatialSound) читают данные зала и 3D-вид **без** собственного движка и без второй модели данных.

## 2. Сущности (предварительно)

Имена типов и полей ниже — рабочие предложения, не готовые API.

### Seat (место)

| Поле (черновик) | Смысл |
|-----------------|--------|
| `id` | Уникальный идентификатор места в рамках сеанса/зала |
| `row` | Ряд |
| `number` | Номер места в ряду |
| `category` | Категория (влияет на цену) |
| `price` | Цена |
| `status` | `free` \| `sold` (и при необходимости `reserved`) |
| `position` | Координаты кресла в пространстве зала |

### Screen (экран)

| Поле (черновик) | Смысл |
|-----------------|--------|
| размеры | ширина / высота экрана |
| расположение | положение в пространстве зала |

### HallGeometry (геометрия зала)

Набор мест, экрана и опорных точек (проходы, колонки — если нужны SpatialSound), достаточный для схемы и 3D.

## 3. Предлагаемые операции (не реализованы)

Пока без привязки к файлам и HTTP/SDK. Cursor заменит это на фактические функции/хуки/эндпоинты.

| Операция | Назначение | Потребители |
|----------|------------|-------------|
| получить геометрию зала сеанса | схема + координаты | все модули |
| получить список мест со статусами и ценами | выбор / рекомендации | SeatMatch, покупка |
| получить место по `id` | детали одного кресла | все |
| получить 3D-вид / параметры камеры для места | перспектива с кресла | SeatCompare, HonestView, UI выбора |
| отметить место купленным | после успешной покупки | только ядро Cursor |
| зарегистрировать модуль опыта | точка расширения UI | SeatMatch / Compare / HonestView / SpatialSound |

## 4. Подключение дополнительных модулей

Предварительный принцип:

1. Ядро Cursor владеет сценой, камерой и покупкой.
2. Модули MiniMax — отдельные компоненты/сервисы в своей зоне файлов.
3. Модули **вызывают** контрактные операции ядра; не дублируют рендер и хранилище.
4. Точка монтирования в UI (кнопка, панель, шаг) определяется Cursor при интеграции.
5. Пока пути файлов не существуют — MiniMax не создаёт параллельный `src/...` «как будто контракт уже в коде». Сначала ждёт утверждения Cursor или явного ТЗ Codex с разрешёнными путями.

## 5. Правила изменения контракта

1. Черновик можно уточнять в обсуждении.
2. После первой реализации ядра Cursor записывает сюда **фактические** имена экспортов/маршрутов и ставит статус «утверждено».
3. Breaking-изменения только через запись в `docs/DECISIONS.md` (делает Cursor) и обновление этого файла.
4. Codex может предложить правки контракта в аудите/ТЗ, но не правит файлы ядра одновременно с Cursor/Cline.

## 6. Чеклист перед интеграцией модуля MiniMax

- [ ] Cursor подтвердил фактический интерфейс в этом файле (статус «утверждено»).
- [ ] Модуль не создаёт второй 3D-движок.
- [ ] Модуль не вводит свою модель Seat.
- [ ] Модуль работает только со свободными/занятыми статусами из ядра.
- [ ] Есть запись в `docs/CLINE_PROGRESS.md`.
- [ ] Cursor перенёс итог в `docs/TASKS.md` после merge.
