# Совместная работа агентов — хакатон «Код Единства»

Этот файл — протокол для Cursor и Codex CLI.  
**Командное разделение двух разработчиков** (Cursor + Cline/MiniMax), ветки Git, приоритеты продукта и порядок сдачи задаёт `docs/TEAM_PROTOCOL.md`.  
Контракт модулей: `docs/INTEGRATION_CONTRACT.md`.

Конкурсный продукт: «Билет с видом на экран». Здесь — только координация агентов, не дублирование всего ТЗ.

Цель: пользователь ставит задачу в одном окне. Cursor делает свою зону. Cline/MiniMax параллельно делает зону опыта в отдельной ветке. Codex подключается официальным CLI для ТЗ, архитектуры и аудита. К человеку обращаемся, если запуск невозможен, нужен платный API или не хватает решения.

## Роли

### Cursor Agent — исполнитель A (ядро)

Делает сам, в ветке `feat/cursor-core`:

- архитектуру, backend, схему зала, покупку билетов;
- основной 3D-рендерер, камеры и перспективу;
- общие маршруты, конфигурацию, сборку, интеграцию и деплой;
- обновление `docs/TASKS.md` и `docs/DECISIONS.md`;
- финальное объединение модулей MiniMax в стабильный `main`.

Не переписывает модули SeatMatch / SeatCompare / HonestView / SpatialSound без согласования.  
Учитывает `docs/INTEGRATION_CONTRACT.md` и подтверждает фактические интерфейсы перед интеграцией.

### Cline + MiniMax M3 — исполнитель B (модули опыта)

Работает по `.clinerules/01-minimax-executor.md` и `docs/TEAM_PROTOCOL.md`.  
Ветка: `feat/cline-experience`.  
Зона: SeatMatch, SeatCompare, HonestView, SpatialSound (+ их UI/тесты).  
Журнал: `docs/CLINE_PROGRESS.md`. Не редактирует `docs/TASKS.md` / `docs/DECISIONS.md`.  
Cline не применяет этот файл как свои runtime-правила; для MiniMax требования продублированы в `.clinerules/`.

### Codex — ТЗ, архитектура, аудит

Подключать Codex, если задача про:

- архитектуру, границы модулей, модель данных, контракты;
- подготовку ТЗ для MiniMax;
- ошибку через несколько слоёв;
- аудит корректности, безопасности или готовности к сдаче.

Codex — отдельный процесс `codex exec`, а не смена модели в чате Cursor. Не писать, что модель переключена, если переключение не выполнено.  
Codex не редактирует одновременно те же файлы, над которыми работают Cursor или Cline.

### OpenRouter — резерв

Только если Cursor или Codex уже сообщили, что лимит подписки исчерпан.

- Не вызывать OpenRouter и любые другие платные API без явного подтверждения пользователя.
- Не создавать ключи, не читать секреты и не обходить лимиты другим провайдером, флагом или повторным запросом.
- Пока подтверждения нет, остановиться и передать текст задания.

## Перед каждой задачей (Cursor / Codex)

1. Прочитать `docs/TEAM_PROTOCOL.md`, `docs/TASKS.md` и `docs/DECISIONS.md`.
2. Убедиться, что работа идёт в правильной ветке (`feat/cursor-core` для разработки ядра; `main` — только стабильная интеграция по согласованию).
3. Оценить сложность и выбрать исполнителя: `cursor`, `codex`, передача зоны MiniMax, или остановка ради OpenRouter.
4. Проверить таблицу «Активные блокировки». Не менять файлы другого исполнителя и зону MiniMax.
5. Записать задачу и файлы в `docs/TASKS.md`. Занять блокировку до первой правки.

Короткий выбор:

- ядро, покупка, зал, 3D, backend, интеграция → Cursor;
- SeatMatch / SeatCompare / HonestView / SpatialSound → MiniMax (через ТЗ Codex при необходимости);
- спроектируй контракт, сквозная ошибка, аудит готовности → Codex;
- лимит исчерпан → остановиться и спросить про OpenRouter.

## Git (кратко)

- Параллельная работа только в `feat/cursor-core` и `feat/cline-experience`.
- Не пушить продукт напрямую в `main`.
- Запрещены force push, `reset --hard`, удаление чужих коммитов, автослияние конфликтов.
- Подробности — в `docs/TEAM_PROTOCOL.md`.

## Запуск Codex

Ничего не устанавливать. Сначала проверить CLI, без обращения к платным API:

```bash
codex --version
codex login status
```

На момент настройки системы: `codex-cli 0.153.4`, вход через ChatGPT. Если статус изменился, верить фактической проверке, а не этой строке.

Если `codex` есть и вход выполнен, записать задание в `docs/codex-prompt.md` по шаблону ниже и запустить из корня проекта:

```bash
scripts/run-codex.sh write docs/codex-prompt.md
scripts/run-codex.sh read-only docs/codex-prompt.md
```

`write` — когда Codex должен менять заранее перечисленные файлы. `read-only` — аудит и проверка готовности без правок.

Скрипт разрешает только песочницу `workspace-write` (с `--approve-for-me`) или `read-only`. Он не принимает обход песочницы, `danger-full-access`, смену модели и установку пакетов. Последний ответ Codex попадает в `docs/codex-last.md`.

Пока Codex выполняется, Cursor не редактирует заблокированные файлы и журналы. После завершения Cursor снимает блокировку, переносит итог в `docs/TASKS.md` и при необходимости дописывает решение в `docs/DECISIONS.md`.

`codex review` смотрит diff и требует git-репозиторий. Для аудита без правок — `read-only`.

Если CLI нет, вход не выполнен, команда ждёт подтверждения вне чата или завершилась ошибкой лимита либо песочницы:

- не повторять запуск с опасными флагами и не ставить Codex заново;
- написать пользователю точную команду и полный текст задания.

Команда для ручного запуска в корне проекта:

```bash
scripts/run-codex.sh write docs/codex-prompt.md
```

```text

Контекст: <факты из TEAM_PROTOCOL, TASKS, DECISIONS, INTEGRATION_CONTRACT>

```

## OpenRouter, если лимит исчерпан

Сообщить:

1. Какой исполнитель остановился и что уже сделано.
2. Полный текст задания, включая файлы и ожидаемый результат.
3. Вопрос: «Подтверждаете разовый запуск через OpenRouter? Назовите модель и явно подтвердите расход API.»

До ответа API не вызывать.

## Общие ограничения

- Один файл в один момент меняет один исполнитель.
- `docs/TASKS.md` и `docs/DECISIONS.md` пишет только Cursor; MiniMax пишет `docs/CLINE_PROGRESS.md`.
- Не утверждать, что модель чата переключена, если это не произошло.
- Не использовать платные API без подтверждения.
- Не обходить лимиты подписок.
- Ответы, планы и отчёты писать на русском.
- После задачи запустить уже существующие проверки проекта и кратко сообщить результат. Если набора проверок ещё нет, так и написать.
